# TaskFlow · 个人任务与进度管理系统

> 企业级 AI 软件设计与开发课程实践项目  
> 一个「任务全生命周期管理 + 进度统计可视化 + AI 智能规划」的个人效率工具

---

## 1. 项目背景与目标

课程作业、科研任务和日常计划常常分散在不同载体（备忘录、聊天记录、脑内）中，缺乏统一的记录、跟踪与回顾机制，导致：

- 截止日期靠记忆，经常逾期才发现；
- 多线任务并行时无法判断「先做什么」；
- 阶段性回顾（本周做了什么、完成率多少）依赖手工整理。

本项目目标是构建一个**个人任务与进度管理系统**，完成任务从 **创建 → 执行 → 状态更新 → 进度统计** 的完整管理闭环：

| 目标    | 说明                                |
| ----- | --------------------------------- |
| 统一入口  | 所有任务集中记录，包含内容、截止时间、优先级、执行状态       |
| 过程可控  | 任务状态可流转（待办 → 进行中 → 已完成），支持随时编辑与删除 |
| 风险前置  | 根据截止日期自动识别逾期任务并醒目提示               |
| 结果可量化 | 完成率、状态分布、逾期数量等统计数据随操作实时更新         |
| AI 增效 | （可选扩展）AI 拆解复杂任务、生成执行计划、自动总结本周完成情况 |

## 2. 产品需求文档（PRD）

### 2.1 用户画像

| 维度   | 描述                                           |
| ---- | -------------------------------------------- |
| 目标用户 | 学生、科研人员、独立开发者等需要自我管理的个人用户                    |
| 使用场景 | 每天 1～5 分钟的碎片化操作：早晨查看今日待办、随手新建任务、完成时勾选、周末回顾统计 |
| 核心诉求 | 记录快、状态清晰、逾期不漏、进度看得见                          |

### 2.2 核心用户故事

1. **作为学生**，我想快速新建一条「周五前提交实验报告」，并标记为高优先级，以便系统在临近截止时提醒我。
2. **作为用户**，我想把一个任务从「待办」推进到「进行中」再到「已完成」，以便统计我的真实完成情况。
3. **作为用户**，我希望逾期任务被自动标红，而不是靠我自己翻日历。
4. **作为用户**，我想按「状态」或「优先级」筛选任务，并按截止日期排序，以便决定今天先做什么。
5. **作为用户**，我想在首页一眼看到：总任务数、完成率、逾期数，以便掌握整体进度。
6. **作为用户（AI 扩展）**，我想输入「准备期末答辩」这样一句话，让 AI 帮我拆解成若干带截止时间的子任务。
7. **作为用户（AI 扩展）**，我想每周日让 AI 自动总结「本周完成了什么、哪些逾期、下周建议」。

### 2.3 功能需求

#### 2.3.1 必做功能（P0）

| 编号   | 功能     | 详细要求                                                         |
| ---- | ------ | ------------------------------------------------------------ |
| F-01 | 任务新增   | 录入标题（必填）、描述（选填）、截止日期、优先级；提交后立即入库并在列表可见                       |
| F-02 | 任务查看   | 列表展示全部任务，卡片含标题、优先级徽章、截止日期、状态标签；支持查看详情                        |
| F-03 | 任务编辑   | 可修改标题、描述、截止日期、优先级、状态；保存后列表与统计同步刷新                            |
| F-04 | 任务删除   | 支持删除（带二次确认），删除后从列表与统计中移除                                     |
| F-05 | 状态管理   | 状态机：`待办(pending)` → `进行中(doing)` → `已完成(done)`；已完成与未完成任务明确区分 |
| F-06 | 截止日期管理 | 录入合法日期（不可早于当天新建时的校验可放宽为提示）；到期日临近（≤3 天）与已逾期做差异化视觉标识           |
| F-07 | 优先级设置  | 三级：`高(high)` / `中(medium)` / `低(low)`，列表以徽章区分                |
| F-08 | 筛选     | 按状态（全部/待办/进行中/已完成）、按优先级筛选，可叠加                                |
| F-09 | 排序与搜索  | 按截止日期（升序/降序）、按优先级排序；标题关键词模糊搜索                                |
| F-10 | 进度统计   | 展示：任务完成率、状态分布、逾期数量（至少一种，本项目做全三种）；数据随任务增删改**实时更新**            |

#### 2.3.2 可选 AI 扩展（P1）

| 编号    | 功能      | 详细要求                                                                     |
| ----- | ------- | ------------------------------------------------------------------------ |
| AI-01 | AI 拆解任务 | 输入一句复杂目标（如「两周内完成课程大作业」），调用 LLM 生成结构化子任务列表（标题 + 建议截止日 + 优先级），用户可勾选后一键批量创建 |
| AI-02 | AI 周报总结 | 汇总本周任务数据（新增/完成/逾期明细），由 LLM 生成一段自然语言的周完成情况总结与下周建议                         |
| AI-03 | 失败兜底    | AI 接口不可用或返回非法 JSON 时，给出友好错误提示并可重试，**不得影响核心任务管理功能**                       |

### 2.4 关键业务规则

| 编号   | 规则                                                                        | 验收判定方式                            |
| ---- | ------------------------------------------------------------------------- | --------------------------------- |
| R-01 | **逾期识别**：`status ≠ done` 且 `截止日期 < 今天(本地时区)` 的任务自动标记为「已逾期」，与截止当天的「今天到期」区分 | 教师现场把某任务截止日期改为昨天 → 列表/统计中立即出现逾期标记 |
| R-02 | **状态区分**：仅 `done` 计入「已完成」；完成率 = 已完成数 ÷ 总任务数（总任务数不含已删除任务）                  | 现场完成一个任务 → 完成率与状态分布图同步变化          |
| R-03 | **数据闭环**：任务持久化到数据库，重启应用后数据不丢失                                             | 现场新增 → 重启 → 数据仍在                  |
| R-04 | **统计实时性**：任何增删改操作后统计数字与图表立即重算，无需手动刷新                                      | 现场操作验证                            |
| R-05 | **排序与置底**：已完成的任务永远排在列表最后；默认「智能排序」按「逾期 → 高优先级 → 截止日近」排列                    | 勾选完成一个任务 → 它自动下沉到列表底部             |

### 2.5 异常与边界处理

| 场景      | 处理方式                             |
| ------- | -------------------------------- |
| 空标题提交   | 前端拦截 + 后端 400 校验，提示「任务标题不能为空」    |
| 非法/缺失日期 | 格式校验（`YYYY-MM-DD`），非法值拒绝入库并提示    |
| 重复快速提交  | 按钮提交后短时禁用（防抖）+ 后端幂等处理，避免同一任务重复创建 |
| 无效状态流转  | 只允许合法状态值；编辑接口对未知状态返回 400         |
| 删除不存在任务 | 返回 404 与友好提示，前端列表同步移除            |
| 搜索无结果   | 展示空状态插画与「新建任务」引导，而非白屏            |
| AI 接口失败 | 超时/异常捕获，提示可重试，不影响主流程             |

### 2.6 数据模型

**tasks 表（SQLite）**

| 字段           | 类型                              | 说明                           |
| ------------ | ------------------------------- | ---------------------------- |
| id           | INTEGER PK AUTOINCREMENT        | 主键                           |
| title        | TEXT NOT NULL                   | 任务标题（1~100 字）                |
| description  | TEXT NOT NULL DEFAULT ''        | 描述（≤1000 字）                  |
| due_date     | TEXT NOT NULL                   | 截止日期 `YYYY-MM-DD`            |
| priority     | TEXT NOT NULL DEFAULT 'medium'  | `high` / `medium` / `low`    |
| status       | TEXT NOT NULL DEFAULT 'pending' | `pending` / `doing` / `done` |
| client_token | TEXT UNIQUE（可空）                 | 幂等令牌，防重复提交                   |
| created_at   | TEXT NOT NULL                   | 创建时间 ISO 8601                |
| updated_at   | TEXT NOT NULL                   | 最后更新时间 ISO 8601              |

索引：`idx_tasks_status`、`idx_tasks_due_date`。另有 `ai_logs` 表记录每次 AI 调用的动作、输入/输出摘要与成功标记，便于回溯演示过程中的 AI 行为。

**派生字段（不入库，查询时计算）**：`isOverdue`（未完成且已过截止日）、`isDueToday`（未完成且今天到期）、`daysUntilDue`（距截止天数，负数即已逾期）。

### 2.7 API 设计（RESTful）

| 方法     | 路径                       | 说明                                                                                                              | 失败码       |
| ------ | ------------------------ | --------------------------------------------------------------------------------------------------------------- | --------- |
| GET    | `/api/health`            | 健康检查（含数据库驱动与库路径）                                                                                                | —         |
| GET    | `/api/tasks`             | 任务列表，支持 `?status=&priority=&sort=&order=&q=`                                                                    | 400       |
| GET    | `/api/tasks/:id`         | 任务详情                                                                                                            | 404       |
| POST   | `/api/tasks`             | 新建任务（`client_token` 幂等，重复返回 `duplicated:true`）                                                                  | 400       |
| PUT    | `/api/tasks/:id`         | 更新任务（含状态流转，局部更新）                                                                                                | 400 / 404 |
| DELETE | `/api/tasks/:id`         | 删除任务                                                                                                            | 404       |
| GET    | `/api/stats`             | 返回 `{total, done, doing, pending, overdue, dueToday, completionRate, statusDistribution, priorityDistribution}` | —         |
| POST   | `/api/tasks/bulk`        | 批量创建（AI 拆解结果一键落库，≤20 条，逐条带幂等令牌）                                                                                 | 400       |
| GET    | `/api/ai/status`         | （扩展）`{enabled, protocol}`                                                                                       | —         |
| POST   | `/api/ai/breakdown`      | （扩展）AI 拆解任务                                                                                                     | 400 / 502 |
| POST   | `/api/ai/weekly-summary` | （扩展）AI 周报总结                                                                                                     | 502       |

统一响应：成功 `{ data: ... }`，失败 `{ error: { code, message } }`。

### 2.9 非功能需求

- **性能**：个人规模数据（< 1000 条）下，列表与统计接口响应 < 200ms；
- **兼容性**：Chrome / Edge 现代浏览器，响应式适配 ≥ 1024px 桌面宽度；
- **可维护性**：前后端分离、接口分层（路由 → 服务 → 数据访问）、统一错误处理中间件；
- **可移植性**：SQLite 单文件数据库，零外部依赖服务即可运行（AI 扩展为可选配置）。

## 3. 技术选型

### 3.1 选型结论

| 层         | 技术                                                                                                                                                     | 版本                            |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------- |
| 运行时       | Node.js                                                                                                                                                | ≥ 18（推荐 22 LTS；22.5+ 可免装原生模块） |
| 后端框架      | Express                                                                                                                                                | 4.x                           |
| 数据库       | SQLite                                                                                                                                                 | 3.x                           |
| SQLite 驱动 | better-sqlite3（可选依赖）→ 装不上时自动回退 Node 内置 `node:sqlite`                                                                                                   | 11.x                          |
| 前端框架      | Vue 3（`<script setup>` 组合式 API）                                                                                                                        | 3.x                           |
| 构建工具      | Vite                                                                                                                                                   | 5.x                           |
| 图表        | Chart.js（状态与优先级分布环形图）                                                                                                                                  | 4.x                           |
| HTTP 客户端  | 原生 `fetch`                                                                                                                                             | —                             |
| 测试        | Node.js 内置 `node:test`                                                                                                                                 | —                             |
| AI 接入     | 双协议兼容层：**Anthropic Messages**（`x-api-key` + `/v1/messages`）与 **OpenAI 兼容**（`Bearer` + `/chat/completions`），按 Base URL 自动识别；JSON 解析加固 + 纠错重试，凭证走 `.env` | —                             |

### 3.2 选型理由

1. **Node.js + Express**：单语言全栈（JS/TS），开发与部署心智负担最低；Express 生态成熟、中间件模式清晰，异常处理与分层结构便于体现「代码结构与质量」得分项；启动一条命令即可，方便教师现场验收。
2. **SQLite**：零配置、单文件，天然满足「数据持久化 + 重启不丢」的验收要求，且便于把 `task.db` 文件直接展示给教师证明数据闭环。驱动采用**双保险**：优先 better-sqlite3（声明为 optionalDependencies，装不上也不阻塞安装），失败则自动回退到 Node 22.5+ 内置的 `node:sqlite`，两者 API 一致，上层代码无感知。
3. **Vue 3 + Vite**：组合式 API 表达力强，Vite 热更新开发体验好、构建产物小；配合响应式数据绑定，统计区可做到「操作即刷新」，直接命中 R-04 规则。
4. **Chart.js**：轻量（相对 ECharts），满足环形图/柱状图需求，5 分钟出效果，契合「界面美观」评分点。
5. **双协议 AI 网关兼容层**：课程允许自由选择 AI 服务，本项目的 `aiService` 同时支持 **Anthropic Messages 协议**与 **OpenAI 兼容协议**，并按 `AI_BASE_URL` 自动识别（路径含 `/anthropic` 走前者，否则走后者，也可由 `AI_PROTOCOL` 显式指定）。当前线上配置为阿里云百炼网关（`qwen-plus`）。由于 Anthropic 协议无 `response_format` 参数，JSON 结构化输出改由「提示词约束 + 稳健解析（去代码块 / 截取首尾花括号）+ 解析失败纠错重试」三重保障，实测稳定。

> 备选方案：Java/Spring Boot + MySQL（更「企业级」但样板代码多、启动慢）、Python/Flask + SQLAlchemy（简洁但前端配合需另起模板引擎）。综合「现场演示启动速度、界面美观度、AI 扩展灵活度」三个验收维度，Node 全栈为最优解。

## 5. 启动方法

> 环境要求：Node.js ≥ 18（推荐 22 LTS）。AI 扩展为可选项，不配置不影响核心功能。

### 方式一：单端口一键启动（推荐用于演示）

```bash
cd server && npm install && npm start     # 后端（含静态托管）
cd client && npm install && npm run build # 构建前端产物到 client/dist

# 浏览器打开 http://localhost:3000
```

构建过一次后，后续演示只需 `cd server && npm start` 一条命令。

### 方式二：前后端分离开发模式（改代码热更新）


## 6. 核心功能演示路径（验收脚本）

1. **新增**：点击「+ 新建任务」→ 填写「提交实验报告 / 截止日期一周后 / 高优先级」→ 保存 → 列表出现新卡片，指标卡「任务总数」+1；
2. **状态流转**：将任务推进为「进行中」→「已完成」→ 完成率、状态分布图实时变化；
3. **逾期识别**（R-01）：现场编辑某未完成任务，截止日期改为昨天 → 卡片标红「已逾期 1 天」，指标卡「已逾期」+1；改为今天则显示橙色「今天到期」；
4. **筛选 / 排序 / 搜索**：状态 Tab（带数量）切换待办/进行中/已完成；叠加优先级筛选；切换排序方式与升降序；搜索框（300ms 防抖）实时过滤；
5. **智能排序与置底**（R-05）：默认「智能排序」= 逾期 → 高优先级 → 截止日近；**勾选完成任一任务，它会立刻下沉到列表底部**；
6. **异常处理**：提交空标题 → 前端拦截；快速连点提交 → 只产生一条（幂等令牌）；删除带二次确认；
7. **数据闭环**（R-03）：新增若干任务 → `Ctrl+C` 停掉服务 → 重新启动 → 刷新，数据完整保留、统计一致（可展示 `server/db/task.db` 文件）；
8. **AI 任务规划**（AI-01）：点击右下角悬浮「AI 助手」（**可拖拽，双击复位**）→ 输入「两周内完成课程大作业」→ AI 生成 3~8 条带截止日与优先级的子任务 → 可逐条编辑/勾选 → 「一键创建 N 条」→ 列表新增多条、统计同步 +N。同一批结果重复点击不会重复落库。
9. **AI 周报总结**（AI-02）：切到第二个 Tab → 基于真实数据生成「本周总结 / 亮点 / 风险 / 改进建议」→ 可导出 Word（.doc）、Markdown（.md）、纯文本（.txt），或一键复制（导出在浏览器本地完成，断网可用）。

> 完整逐镜头录像脚本（含时间轴、要说的话、翻车预案）见 `docs/演示视频脚本.md`。

## 7. AI 辅助开发情况说明

本项目按课程要求，AI（WorkBuddy / Claude Code 等 AI 编程工具）深度参与开发全过程：

| 环节     | AI 的参与方式                                                                        |
| ------ | ------------------------------------------------------------------------------- |
| 需求分析   | 将课程验收标准（.docx，含一张内嵌图片的评分表，需先还原）投喂给 AI，共同梳理出功能清单、业务规则（R-01～R-05）与异常场景矩阵，产出本 PRD |
| 技术选型   | 由 AI 对比 Spring Boot / Flask / Node 三套栈在「现场启动速度、界面美观、AI 扩展成本」上的差异并给出决策依据（见 §3.2） |
| 代码生成   | 后端分层骨架（路由/服务/DAO/错误中间件）、前端组件（统计卡片、任务卡片、表单弹层）由 AI 依据 PRD 生成初稿，人工 review 后采纳      |
| 业务规则实现 | 逾期判定（时区安全的日期比较）、完成率计算等关键函数由 AI 生成并附单元测试                                         |
| 调试     | 将报错原样交给 AI 定位根因并给修复 patch：① better-sqlite3 原生编译失败（改双驱动回退）② 数据库路径多拼一层 ③ 修改 DAO 时函数头重复导致语法错误（用 `node --check` 定位）④ Vite 清空 dist 被拦截 ⑤ AI 网关协议判断错误（实测非 OpenAI 协议） |
| 代码审查   | 让 AI 以「评审者」角色检查重复代码、硬编码密钥、未处理的 Promise 异常等问题并重构                                 |
| 测试     | AI 生成接口级测试用例（空标题、非法日期、不存在 id 的 PUT/DELETE 等），覆盖 §2.5 全部异常场景                     |

**关键 Prompt 示例**：

> 「基于以下 PRD 的数据模型与 API 设计，用 Express 4 + better-sqlite3 实现 GET /api/tasks，要求支持 status/priority 筛选、按 due_date/priority 排序、标题模糊搜索，参数校验失败返回 400，并编写错误处理中间件。」

**AI 功能的产品化 Prompt（运行时）**：

- AI-01 任务拆解系统提示词：要求模型只输出 `{"subtasks":[{"title":"...","due_date":"YYYY-MM-DD","priority":"high|medium|low","estimate":"..."}]}`，约束「3~8 条、按依赖顺序、日期从起始日递增、标题 ≤ 20 字」。
- AI-02 周报总结系统提示词：把真实统计（总数/完成/进行中/待办/逾期/完成率）、近 7 天新增、完成清单、逾期清单序列化后喂给模型，要求输出 `{"summary":"","highlights":[],"risks":[],"suggestions":[]}`，并明确「引用真实数据，不要编造任务」。
- 由于 Anthropic Messages 协议不支持 `response_format`，JSON 结构化改由**提示词约束 + 稳健解析（剥离代码块 → 截取首尾花括号）+ 解析失败带错误样本纠错重试**保障；仍失败则返回 502 友好提示，核心任务功能不受影响。
