# TaskFlow 开发设计文档

> 本文档回答「**怎么设计与实现的**」：架构分层、数据模型、接口契约、业务规则、前端交互、AI 设计与测试策略。

---

## 1. 整体架构

```
┌──────────────────────────────────────────────────┐
│  Vue 3 前端（Vite 5 构建 → client/dist）            │
│  App.vue 持有全局状态（tasks / stats / filters）     │
│  ├ StatCards            4 张指标卡                 │
│  ├ DistributionCharts   状态分布 + 优先级分布双环形图 │
│  ├ FilterBar            状态 Tab / 优先级 / 排序 / 搜索│
│  ├ TaskCard             任务卡片（勾选 · 编辑 · 删除）│
│  ├ TaskFormModal        新建 / 编辑表单弹层          │
│  └ AiAssistant          悬浮 AI 助手（可拖拽）        │
│      ├ Tab1 任务规划：目标 → 子任务 → 勾选 → 批量创建 │
│      └ Tab2 周报总结：真实数据 → 总结 → 导出/复制    │
└───────────────┬──────────────────────────────────┘
                │ REST / JSON（同源 /api；dev 由 Vite 代理到 3000）
┌───────────────▼──────────────────────────────────┐
│  Express 4 后端                                    │
│  ├ routes/     路由：参数透传 + 状态码（只做薄壳）    │
│  ├ services/   业务规则 + 输入校验（R-01~R-04 在此） │
│  ├ dao/        SQL 数据访问（唯一出现 SQL 的地方）    │
│  ├ middleware/ AppError → HTTP 状态码统一映射        │
│  ├ utils/date  本地时区日期工具（逾期判定的基础）      │
│  └ db/         连接 + 建表 + 驱动适配                │
└───────┬──────────────────────────┬────────────────┘
        │                          │ 可选（未配置则降级）
┌───────▼────────┐        ┌────────▼───────────────────┐
│ SQLite 单文件   │        │ AI 网关（双协议适配层）       │
│ server/db/task.db│       │ Anthropic /v1/messages      │
│ WAL 模式        │        │ 或 OpenAI /chat/completions  │
└────────────────┘        └─────────────────────────────┘
```

### 1.1 分层原则

| 层 | 职责 | 禁止 |
|---|---|---|
| `routes/` | 取参数、调 service、定状态码（201 / 200 / 204） | 写业务判断、写 SQL |
| `services/` | 输入校验（normalize*）、业务规则、派生字段计算 | 直接拼 SQL |
| `dao/` | 纯 SQL 与结果映射 | 承载业务规则 |
| `middleware/` | `AppError` → HTTP 状态码与统一响应体 | — |

错误在 service 中以 `badRequest / notFound / upstreamError` 抛出，由 `errorHandler` 统一转成 `{ error: { code, message } }`。路由无需 try/catch 模板代码（异步路由除外，需 `next(err)`）。

### 1.2 部署形态

- **生产/演示**：`client/dist` 由 Express `express.static` 托管，`npm start` 单端口 **3000** 打开完整应用；SPA 兜底路由 `app.get('*')` 回 `index.html`。若 dist 不存在则仅提供 API。
- **开发**：前端 5173（Vite HMR）+ `/api` 代理到 3000。

## 2. 数据模型

### 2.1 tasks

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK AUTOINCREMENT | 主键 |
| title | TEXT | NOT NULL | 标题，后端校验 1~100 字 |
| description | TEXT | NOT NULL DEFAULT '' | 描述，≤1000 字 |
| due_date | TEXT | NOT NULL | 截止日期 `YYYY-MM-DD`，真实日期校验 |
| priority | TEXT | NOT NULL DEFAULT 'medium' | `high` / `medium` / `low` |
| status | TEXT | NOT NULL DEFAULT 'pending' | `pending` / `doing` / `done` |
| client_token | TEXT | UNIQUE（可空） | 幂等令牌 |
| created_at | TEXT | NOT NULL | ISO 8601 |
| updated_at | TEXT | NOT NULL | ISO 8601，更新时自动刷新 |

索引：`idx_tasks_status`、`idx_tasks_due_date`，加速筛选与排序。

**为什么用字符串存日期**：SQLite 无原生日期类型；`YYYY-MM-DD` 的字典序等于时间序，可直接用 `<` / `=` 比较，避免时区转换带来的跨日误差。

### 2.2 ai_logs

```sql
CREATE TABLE ai_logs (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  action     TEXT NOT NULL,        -- 'breakdown' | 'weekly-summary'
  payload    TEXT NOT NULL DEFAULT '',  -- 输入摘要（截断 2000 字）
  result     TEXT NOT NULL DEFAULT '',  -- 输出摘要
  success    INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL
);
```

作用：回溯演示/调试过程中的 AI 行为，便于事后核查「AI 是否真的被调用、喂了什么数据」。写日志失败只 warn 不抛错，**绝不因日志影响主流程**。

### 2.3 派生字段（不入库，查询时计算）

| 字段 | 计算方式 |
|---|---|
| `isOverdue` | `status !== 'done' && due_date < today` |
| `isDueToday` | `status !== 'done' && due_date === today` |
| `daysUntilDue` | `due_date - today`（天，负数表示已逾期） |

`today()` 与 `diffDaysFromToday()` 位于 `utils/date.js`，内部把日期转成 UTC「天序号」再求差，规避本地时区/夏令时造成的跨日误差。

## 3. 接口契约

统一响应：成功 `{ data: <payload> }`；失败 `{ error: { code, message, details? } }`。

| 方法 | 路径 | 说明 | 成功码 | 失败码 |
|---|---|---|---|---|
| GET | `/api/health` | 健康检查（返回 ok / 驱动名 / db 路径） | 200 | — |
| GET | `/api/tasks` | 列表，参数见 3.1 | 200 | 400 |
| GET | `/api/tasks/:id` | 详情 | 200 | 404 |
| POST | `/api/tasks` | 新建，支持 `client_token` 幂等 | 201（重复 200 + `duplicated:true`） | 400 |
| POST | `/api/tasks/bulk` | 批量创建（AI 子任务落库），≤20 条 | 201 | 400 |
| PUT | `/api/tasks/:id` | 局部更新（含状态流转） | 200 | 400 / 404 |
| DELETE | `/api/tasks/:id` | 删除 | 200 | 404 |
| GET | `/api/stats` | 统计，见 3.2 | 200 | — |
| GET | `/api/ai/status` | `{ enabled, protocol }` | 200 | — |
| POST | `/api/ai/breakdown` | AI 拆解任务 | 200 | 400 / 502 |
| POST | `/api/ai/weekly-summary` | AI 周报总结 | 200 | 502 |

### 3.1 GET /api/tasks 查询参数

| 参数 | 取值 | 默认 | 说明 |
|---|---|---|---|
| `status` | `pending` / `doing` / `done` | 空（全部） | 非枚举值 → 400 |
| `priority` | `high` / `medium` / `low` | 空 | 非枚举值 → 400 |
| `sort` | `smart` / `due_date` / `priority` / `created_at` | `smart` | 见 §4.2 |
| `order` | `asc` / `desc` | `asc` | `smart` 排序下忽略 |
| `q` | 字符串（≤100） | 空 | 标题 + 描述 `LIKE %q%` 模糊匹配 |

### 3.2 GET /api/stats 响应字段

```json
{
  "today": "2026-09-28",
  "total": 12, "done": 4, "doing": 3, "pending": 5,
  "overdue": 2, "dueToday": 1,
  "completionRate": 33.3,
  "statusDistribution":   { "pending": 5, "doing": 3, "done": 4 },
  "priorityDistribution": { "high": 4, "medium": 5, "low": 3 },
  "updatedAt": "2026-09-28T05:00:00.000Z"
}
```

### 3.3 幂等语义

- 单条：客户端传 `client_token`；命中已有记录时返回 **200 + `duplicated:true`**（不是 409，因为「任务已存在」对重试场景是成功语义）。
- 批量：前端为每批生成 `batchId`，子任务令牌为 `batchId#序号`；后端在未传令牌时按 `crypto.randomUUID() + '#' + index` 兜底。因此**同一批 AI 结果连点两次不会重复落库**。

## 4. 业务规则实现

### 4.1 规则清单

| 编号 | 规则 | 实现位置 | 现场验证方式 |
|---|---|---|---|
| R-01 | 逾期识别：`status ≠ done` 且 `due_date < 今天` → 逾期；`= 今天` → 今天到期 | `taskService#decorate` + `dao#countOverdue` / `#countDueToday` | 把某任务截止日改成昨天，卡片标红 +「已逾期 N 天」，统计「已逾期」+1 |
| R-02 | 完成率 = `done / total`，保留一位小数；空库为 0；已完成任务永不标逾期 | `statsService#getStats` | 勾选完成一个任务，完成率与状态分布图同步变化 |
| R-03 | 数据闭环：SQLite 单文件 + WAL，重启不丢 | `db/index.js` | 新增 → 重启服务 → 数据仍在 |
| R-04 | 统计实时：任何写操作后列表与统计同时重算 | `App.vue#refresh`（`Promise.all` 双刷） | 操作后立即观察数字/图表变化，无手动刷新入口 |
| R-05 | 排序：已完成永远置底；默认智能排序（逾期 → 高优先 → 截止近） | `dao#findAll` | 勾选完成后任务自动下沉到列表底部 |

### 4.2 排序策略（`dao/taskDao.js`）

所有排序模式都前置 `doneLast`，保证「已完成置底」这一稳定预期：

```sql
CASE WHEN status = 'done' THEN 1 ELSE 0 END ASC
```

**智能排序（`sort=smart`，默认）** 的 ORDER BY：

```sql
CASE WHEN status = 'done' THEN 1 ELSE 0 END ASC,                                  -- 已完成置底
CASE WHEN status <> 'done' AND due_date < @today THEN 0 ELSE 1 END ASC,           -- 逾期置顶
CASE priority WHEN 'high' THEN 3 WHEN 'medium' THEN 2 ELSE 1 END DESC,            -- 高优先优先
due_date ASC,                                                                     -- 截止近的优先
id DESC
```

其余模式（`@dir` 由 `order` 注入）：

| sort | ORDER BY（已省略前置的 doneLast） |
|---|---|
| `due_date` | `due_date @dir, 优先级 DESC, id DESC` |
| `priority` | `优先级 @dir, due_date ASC, id DESC` |
| `created_at` | `created_at @dir, id DESC` |

> UI 联动：选中「智能排序」时升降序按钮自动禁用并置灰（智能排序无需方向），切回其他模式恢复可用。

### 4.3 异常处理矩阵

| 场景 | 处理 | 状态码 |
|---|---|---|
| 空标题 / 标题 > 100 字 | 前端先拦截；后端 `normalizeText` 兜底 | 400 |
| 非法日期（`2026-02-30`、中文日期、空值） | `isValidDateStr` 真实日期校验 | 400 |
| 非法 status / priority | 枚举白名单 | 400 |
| 重复提交（连点 / 网络重试） | `client_token` 唯一索引命中 → 返回已存在记录 | 200 + duplicated |
| 更新/删除不存在的 id | `notFound` | 404 |
| 更新时无任何有效字段 | `badRequest('没有需要更新的字段')` | 400 |
| 批量创建空数组 / > 20 条 | `badRequest` | 400 |
| 未匹配路由（`/api/*`） | 统一 404 JSON | 404 |
| AI 未配置 / 超时 / 返回非法 JSON | 502 + 弹窗内友好提示 | 502 |

## 5. 前端设计

### 5.1 组件职责

| 组件 | 职责 | 关键实现 |
|---|---|---|
| `App.vue` | 全局状态（tasks / stats / filters）+ 各组件编排 + Toast | `refresh()` 用 `Promise.all` 同时拉列表与统计；`watch(filters, …, {deep:true})` 条件变化即重载 |
| `StatCards.vue` | 4 张指标卡：任务总数 / 完成率 / 今天到期 / 已逾期 | 左侧 3px 色条区分语义（中性/品牌绿/橙/红） |
| `DistributionCharts.vue` | 状态分布 + 优先级分布两张环形图 | Chart.js；实例复用 + `chart.update()` 避免重建闪烁；卸载时 `destroy()` |
| `FilterBar.vue` | 状态 Tab（带数量）/ 优先级 / 排序 / 升降序 / 搜索 | 搜索 300ms 防抖；通过 `emit('update:modelValue', {...})` **整体替换**筛选对象 |
| `TaskCard.vue` | 卡片：勾选完成、状态切换、编辑、删除二次确认 | 逾期卡片红条 +「已逾期 N 天」标签 |
| `TaskFormModal.vue` | 新建 / 编辑表单 | 打开表单即生成新的 `client_token`，提交成功后重建 |
| `AiAssistant.vue` | 悬浮入口 + 双 Tab 弹窗 | 见 5.3 |
| `utils/exporter.js` | 周报导出 | `toMarkdown` / `toWordHtml`(`.doc`) / `toPlainText` / `copyReport`，纯前端 Blob 下载 |

### 5.2 一处值得记录的设计决策：为什么 filters 用 `ref` 而不是 `reactive`

`FilterBar` 通过 `v-model` **整体替换**筛选对象（`emit` 一个新对象）。若 `App.vue` 里写 `const filters = reactive({...})`，`filters = newValue` 会尝试给常量重新赋值而**静默失败**——筛选条件永远不变。这是本项目筛选功能曾完全失效的根因。改为 `ref` 后 `filters.value = newValue` 正常触发响应式更新。

### 5.3 悬浮 AI 助手（`AiAssistant.vue`）

- **入口**：右下角机器人胶囊按钮（呼吸光环 + 轻微浮动）。仅在 `/api/ai/status` 返回 `enabled: true` 时渲染。
- **拖拽**：`pointerdown / pointermove / pointerup` 手写实现（不用 HTML5 `draggable`，固定定位元素拖影难看且不支持触屏）。
  - 按下时把 CSS 的 `right/bottom` 固化成 `left/top` 像素坐标，之后按「起点 + 位移」计算；
  - `clampPos()` 边界收敛，四周留 12px，拖不出视口；
  - 位置存 `localStorage`（`taskflow.ai-fab.pos`），刷新后仍在原处；窗口缩小导致越界时，在 `resize` 与渲染后自动拉回；
  - 位移 > 4px 才判定为拖拽，结束时置 `justDragged` 抑制紧随的 `click`——**否则每次拖完都会误弹面板**；
  - 双击复位到默认位置并清除记忆；拖拽中 `cursor: grabbing`、放大 1.05、关闭过渡动画（避免手感发飘）；
  - `touch-action: none` 防页面滚动，`user-select: none` 防误选文字。
- **Tab 1 任务规划**：输入目标（附示例 chip 一点即填 + 可指定起始日）→ 调 `/api/ai/breakdown` → 子任务列表**可逐条编辑**标题/优先级/截止日 → 勾选（含全选）→「一键创建 N 条」走 `/api/tasks/bulk` → `@created` 通知 App 刷新。
- **Tab 2 周报总结**：调 `/api/ai/weekly-summary` → 渲染「总结 / 亮点 / 风险 / 改进建议」+ 真实统计 chips → 导出 Word（`.doc`）/ Markdown（`.md`）/ 纯文本（`.txt`）或一键复制。

## 6. AI 功能设计

### 6.1 双协议适配层

`services/aiService.js` 对上层只暴露 `callChat(messages)`，内部按配置自动选协议：

| 协议 | 触发条件 | 端点 | 鉴权头 |
|---|---|---|---|
| Anthropic Messages | `AI_BASE_URL` 含 `/anthropic`，或 `AI_PROTOCOL=anthropic` | `{base}/v1/messages` | `x-api-key` + `anthropic-version: 2023-06-01` |
| OpenAI 兼容 | 其余情况，或 `AI_PROTOCOL=openai` | `{base}/chat/completions` | `Authorization: Bearer` |

协议差异在适配层内部消化：

| 差异点 | Anthropic | OpenAI |
|---|---|---|
| system 提示词 | **顶层 `system` 字段**，不进 messages 数组 | messages 数组首条 |
| 长度限制 | `max_tokens` **必填** | 可选 |
| 返回体 | `content[]` 文本块数组（过滤 `type === 'text'` 后拼接） | `choices[0].message.content` |
| 结构化输出 | **无 `response_format`** | 支持 `json_object` |

> 当前线上配置：阿里云百炼网关（`/apps/anthropic`）+ `qwen-plus`，走 Anthropic 协议。
> 这一步是实测出来的：最初按 OpenAI 协议调 `{base}/v1/chat/completions` 返回 **404**，改走 `{base}/v1/messages` 才通。

### 6.2 输出稳定性：三重保障

Anthropic 协议没有 `response_format`，因此结构化输出改为：

1. **提示词约束**：「只输出 JSON，不要解释文字、不要用代码块」，并给出完整结构与字段枚举；
2. **稳健解析** `parseJsonSafely`：原样解析 → 剥离 ```json 包裹 → 截取首尾花括号，三步兜底；
3. **纠错重试**：仍失败时把模型上一条输出（截断 1500 字）回贴，要求重出纯 JSON。

传输层另有 1 次重试（`postJson`），`AbortController` **45s** 超时，`max_tokens` 默认 2048。

字段再做白名单清洗：`priority` 只保留 `high/medium/low`，非法日期回退为「起始日 +3 天」，标题截断 100 字，子任务最多取 10 条且过滤空标题。

### 6.3 数据真实性与降级

- **周报输入**：实时统计（总数/完成/进行中/待办/逾期/完成率）+ 近 7 天新增清单 + 近 30 天完成清单 + 逾期清单，序列化后喂给模型；Prompt 明确「引用真实数据，不要编造任务」。
- **降级**：未配置网关或调用失败 → 502，弹窗内显示错误与重试按钮，**核心 CRUD 完全不受影响**；未配置时顶栏显示灰色「AI 未配置」标签。
- **导出**：在浏览器本地完成（Blob + `URL.createObjectURL`），Word 走带 Office 命名空间的 HTML（`.doc`），断网也能用。

## 7. 测试策略

`server/tests/api.test.js`，`cd server && npm test`（Node.js 内置 `node:test`，无第三方依赖）。

**隔离设计**：

- 测试进程 spawn 起**独立端口 + 独立临时数据库**的服务实例，跑完自动关闭，不污染 `server/db/task.db` 演示数据；
- 显式清空 `AI_BASE_URL / AI_API_KEY / AI_MODEL`，AI 用例走「未配置降级」分支，**不依赖外网、不产生费用**。

**覆盖：31 个用例 / 8 个分组，全部通过（pass 31, fail 0）**

| 分组 | 覆盖点 |
|---|---|
| 健康检查与统计 | `/api/health`、统计字段完整性、空库完成率为 0 |
| 任务创建与校验（异常场景） | 空标题、超长标题、非法日期（2026-02-30）、非法状态/优先级、幂等令牌 |
| 查询：筛选 / 排序 / 搜索 | 按状态、按优先级、关键词模糊匹配、非法枚举 → 400 |
| 业务规则：逾期与统计联动 | 改截止日触发逾期、完成率与逾期数实时联动 |
| 更新与删除 | 状态流转、404、无有效字段 → 400 |
| 智能排序与筛选联动 | 逾期高优先排第一、已完成之后不允许出现未完成任务 |
| 批量创建 | 正常创建、重复提交幂等、空数组/超限/非法字段 |
| AI 扩展降级 | 未配置网关 → 502，且核心任务接口不受影响 |

## 8. 工程决策与踩坑记录

### 8.1 决策

| 决策 | 候选 | 结论与原因 |
|---|---|---|
| 技术栈 | Spring Boot / Flask / Node | **Node**：单语言全栈，现场启动最快，前端生态最好 |
| 数据库 | MySQL / SQLite / JSON 文件 | **SQLite**：零配置单文件，重启不丢，可直接展示 `.db` 证明数据闭环 |
| SQLite 驱动 | better-sqlite3 / node:sqlite | **双驱动**：优先 better-sqlite3（放 `optionalDependencies`，装不上不阻塞），自动回退 Node 22.5+ 内置 `node:sqlite`，两者 API 一致，上层无感知 |
| 图表库 | ECharts / Chart.js | **Chart.js**：体积更小，环形图足够 |
| 部署形态 | 双服务 / 单端口 | **单端口**：`npm start` 直接托管 dist，演示只需一个窗口 |
| 筛选状态 | `reactive` / `ref` | **`ref`**：配合子组件整体替换对象的 v-model 语义（见 §5.2） |

### 8.2 踩过的坑（按发生顺序）

1. **`better-sqlite3` 原生编译失败**：node-gyp 拉取 Node headers 时网络中断，GitHub releases 与 nodejs.org 均不可达。解法：从 npmmirror CDN 取 `node-v127-win32-x64` 预编译二进制手动放入 `build/Release`；同时改为 `optionalDependencies` + `node:sqlite` 回退，保证换机器 `npm install` 不卡死。
2. **数据库路径多了一层**：`db/index.js` 本身在 `server/db/` 下，却再拼了一次 `db/`，导致生成 `server/db/db/task.db`。已改为 `const dbDir = __dirname`。
3. **Edit 工具拼接重复函数头**：修改 `taskDao.js#findAll` 时 `old_string` 从函数中部匹配，导致新旧函数头重复、语法错误、服务起不来。用 `node --check` 定位后修复。教训：**改完 JS 立刻 `node --check`，别等运行时报错**。
4. **Vite `emptyOutDir` 被安全删除拦截**：`vite build` 清空 `dist` 时 `rmSync` 被环境拦截。解法：`vite.config.js` 设 `emptyOutDir: false` + 构建前手动清理 `client/dist`。
5. **AI 网关协议判断错误**：按 OpenAI 协议调 `/v1/chat/completions` 返回 404，实测 `/apps/anthropic` 走的是 Anthropic Messages 协议。已改为双协议自适应（§6.1）。
